# 앱 이벤트 로그 세션화 & 퍼널 · 장바구니 이탈 분석 (SQL 기반)

사용자 행동 이벤트 로그를 SQL 윈도우 함수로 **세션화**하고, 이벤트 퍼널과 세션 내 장바구니 이탈을 분석한 프로젝트입니다.
"주문" 단위가 아닌 "행동" 단위 로그를 다뤄, 유저가 서비스 안에서 어디서 이탈하는지를 지표로 만듭니다.

- **데이터**: [RetailRocket E-Commerce Dataset](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset) (이벤트 로그 275만 건, 2015)
- **기술**: SQL(SQLite, 윈도우 함수), Python(pandas, matplotlib)
- **결과물**: 이벤트 퍼널 · 세션화 로직 · 세션 내 장바구니 이탈률

---

## 왜 이 분석인가

주문 데이터는 "산 사람"만 보여주지만, 이벤트 로그는 "보다가 떠난 사람"까지 보여줍니다.
서비스 개선의 실마리는 대개 이 "떠난 지점"에 있어, 로그를 세션 단위로 잘라 어디서 이탈하는지 산출했습니다.

## 데이터 처리에서 짚은 두 가지

- **밀리초 타임스탬프**: `timestamp`가 초가 아닌 밀리초 epoch라, `datetime(timestamp/1000, 'unixepoch')`로 변환해야 올바른 시각이 나옴.
- **이벤트 단위 로그**: 한 행이 주문이 아니라 행동(view / addtocart / transaction) 1건. 한 유저가 수십 건의 이벤트를 남기므로, 지표는 방문자·세션 단위로 다시 집계해야 함.

## 분석 설계

### 1. 이벤트 퍼널 (방문자 기준)
`COUNT(DISTINCT CASE WHEN ... END)`로 이벤트를 한 번이라도 한 순 방문자 수를 세어, 조회 → 장바구니 → 구매 전환을 산출.

### 2. 세션화 (Sessionization)
윈도우 함수로 유저 행동을 방문 단위로 분리.

```sql
LAG(timestamp) OVER (PARTITION BY visitorid ORDER BY timestamp)  -- 직전 이벤트 시각
```

직전 이벤트와 30분(1,800,000ms)을 초과해 벌어지면 새 세션으로 표시하고, `SUM(...) OVER (...)`로 누적 합산해 세션 번호를 부여. 결과는 별도 테이블(`sessioned`)로 저장해 재사용.

### 3. 세션 내 장바구니 이탈
세션마다 `MAX(CASE WHEN event='addtocart' ...)`, `MAX(CASE WHEN event='transaction' ...)`로 "담았나 / 샀나"를 만들고, 담았지만 같은 세션에서 사지 않은 비율을 산출.

## 핵심 발견

- **규모**: 이벤트 275만 건, 순 방문자 140만 명, 세션 176만 개(세션당 평균 1.56 이벤트 — 짧은 단발성 방문이 다수).
- **이벤트 퍼널**: 조회한 방문자 중 장바구니는 2.7%(37,722명), 구매는 0.8%(11,719명). 장바구니를 담은 방문자의 **약 31%가 최종 구매** → 가장 큰 관문은 "구매 결정"이 아니라 "장바구니까지 끌어오는 단계".
- **세션 내 장바구니 이탈 72.8%**: 장바구니가 담긴 세션 43,924개 중 31,992개가 그 방문에서 구매로 이어지지 않음.
- **교차 검증**: 방문자 기준 장바구니→구매(31%)와 세션 내 장바구니→구매(27%)가 거의 같음 → 담아두고 다음 방문에 다시 와서 사는 경우는 드묾. **이탈 회복은 '다음 알림'보다 '같은 세션 내 전환'을 밀어주는 것이 핵심**이라는 방향을 제시.
